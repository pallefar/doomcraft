THE PLAN, AS NUMBERED CLAUSES

C1. MOVE THE PELLET CLAMP TO SHARED AND APPLY IT ON BOTH SIDES.
    Today `client/src/game/weapons.ts:288` declares `export const MAX_PELLETS =
    16` and `:1107` clamps with
    `const pellets = def.hot.pellets > MAX_PELLETS ? MAX_PELLETS : def.hot.pellets;`
    while `server/src/sim.ts:1092` loops `for (let i = 0; i < def.pellets; i++)`
    with no bound at all.
    PROPOSAL: declare `MAX_PELLETS = 16` in `shared/src/weapons.ts`, re-export it
    from `client/src/game/weapons.ts` so existing importers do not move, and
    clamp the server loop the same way.

C2. THE TWO SIDES MUST READ THE SAME PELLET SOURCE.
    The client reads `def.hot.pellets`, a uint8. The server reads `def.pellets`,
    a JavaScript double. For every shipping weapon these are equal (max is 7).
    PROPOSAL: make the server read `def.hot.pellets` as well, so a pellet count
    of 256 cannot be 0 on one side and 256 on the other.
    THE CLAIM I WANT ATTACKED: that this is a no-op for the shipping table and
    therefore the lockstep golden in `client/src/game/lockstep.test.ts` and the
    cone agreement in `client/src/game/agreement.test.ts` do not move. If it
    DOES move either one, that is a behaviour change and it needs its own
    argument, not a bundled one.

C3. CLAMP `carveSphere`.
    `server/src/world.ts:609` guards only `if (radius <= 0) return 0;`. At
    radius 1e20, `y0 = Math.floor(cyf - 1e20)` is -1e20 and
    `for (let y = y0; y <= y1; y++)` never advances because
    `-1e20 + 1 === -1e20`: one call blocks the event loop forever. NaN is not
    guarded either — `NaN <= 0` is false, so a NaN radius enters the loop.
    PROPOSAL: replace the guard with a finite-and-positive test plus an upper
    clamp to a named constant (proposed: the largest radius any shipping weapon
    can ask for, times a small factor — concretely `TERRAIN_CARVE_MAX_RADIUS`,
    value to be argued, candidate 16). Reject non-finite; clamp above.
    THE CLAIM I WANT ATTACKED: that no shipping call site can pass a radius
    above the chosen constant today, so the clamp cannot change behaviour. The
    largest `terrainDamage` in `shared/src/weapons.ts` is 5.5 (BFG). Find every
    caller of `carveSphere` and say whether the claim holds for all of them,
    including `scorchCrater`'s `radius + 1` and any horde/monster path.
